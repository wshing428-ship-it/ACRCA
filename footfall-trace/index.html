开始后点“手动定位”：在地图上点你站的位置，再点你面朝的方向（贴了二维码的话扫码更准）。手机竖着拿在胸前，屏幕朝上或朝前都可以，顶端指向你走的方向。屏幕要一直亮着，不要锁屏或切到别的 App。

后台记录：手机放口袋，录两个小时也行

网页在锁屏后会停止，所以长时间记录用免费 App Sensor Logger（安卓也有）。录完把导出的 zip 放进来，这里还原成平面图上的轨迹。

  1. Sensor Logger 里只勾 加速度计、重力、陀螺仪、计步器，采样率设 50 Hz；定位权限选“始终允许”（App 说这样后台才不会停）。
  2. 站在一个你在地图上能指出来的位置，按开始，锁屏放口袋。出发后先朝一个明确的方向直走几步（比如沿走廊）。
  3. 离开这层楼时按停止，导出为 Zipped CSV。

参与者

标定步长

量一段直线距离（卷尺，或者两块地砖线之间），站在起点，按“开始”，正常速度直线走到终点停下，再按“结束”。走两三遍取平均更准。每个人走路不一样，所以每人做一次。

传感器测试

走 20 步，看计数是否一致；原地转一圈，看方向是否转回原值。

地图

平面图用图片（PDF 先截图）。墙线越清晰越好，最好是黑线白底的 CAD 导出图。

① 比例尺

先定比例尺再改墙体；改比例尺会清掉手动画的墙。

② 墙体（走不过去的地方）

深浅阈值

橙色 = 墙，绿色 = 手动标为可通行。门洞、门的弧线、文字这些被误判成墙的地方，用“擦除”涂掉；桌子、柜子、柱子这种图上没画但走不过去的，用“画墙”涂上。

③ 锚点（二维码校正点）

扫码时面朝

二维码贴在墙或柱子上，胸口高度。地图上的锚点放在“站着扫码的位置”，箭头指向码（也就是扫码时人面对的方向）。每隔 8–15 米、每个房间门口、拐角放一个最好。楼梯口/电梯口放“出口”码。

分享地图给组员

地图包包含平面图、墙体和锚点。发给组员导入，大家的坐标就是同一套，记录可以叠在一起看。

它怎么知道你在哪

Web 网页拿不到室内定位（GPS 在楼里不准，iPhone 的 Safari 也不能用蓝牙信标和 AR），所以这里用的是步行航位推算：加速度计数步、估计每步多长，陀螺仪给方向，一步一步往前推。纯推算每走 100 步会偏出几米，所以加了三层校正：

  1. 墙体约束：同时跟踪 400 个“候选位置”，穿墙的候选被淘汰。走进门、拐过墙角时，误差会自己收紧。这是最主要的校正，走得越曲折越准。
  2. 二维码锚点：扫码时位置和朝向都重新对准，上一段路径会按时间比例回拉（结束后的轨迹是校正过的）。
  3. 个人步长：每个人先走一段已知距离，算出自己的步长系数。

第一次布置（组里一个人做）

  1. 地图设置 → 上传这层楼的平面图 → 定比例尺 → 检查墙体，涂掉门洞，补上家具。
  2. 放 6–12 个锚点，生成二维码打印出来，按地图贴好。
  3. 导出地图包，发给大家导入。

每个参与者

  1. 步长校准里建自己的名字，走一次 10 米标定。
  2. 记录 → 开始 → 在附近锚点扫码 → 正常走。路过锚点顺手扫一下（建议每 1–2 分钟一次）。
  3. 离开这层楼时扫“出口”码，或者按结束。
  4. 记录库 → 导出 JSON 发给整理数据的人。

精度和限制

情况大概误差
刚扫完码0.3–0.5 m
扫码后走 1 分钟，房间结构曲折约 1 m
扫码后走 3 分钟，大开间2–4 m
  • 手机放兜里、甩手拿着、边走边打字都会变差；拿稳在胸前最好。
  • 网页记录时，锁屏或切走 App 会停掉传感器，这段不会记录。长时间放口袋请用“记录”页里的后台记录（Sensor Logger）。
  • 上下楼梯不会识别，所以只记一层；扫“出口”码自动结束。
  • 数据只存在各自手机的浏览器里，不上传。清浏览器数据前记得导出。

考虑过但没用的方案

方案为什么没用
蓝牙信标 (iBeacon)Web Bluetooth 在 iPhone 上完全不能用；安卓 Chrome 也不能扫信标信号强度。要做就得写原生 App。
WebXR / AR 空间追踪精度最好（厘米级），但 iPhone Safari 不支持 WebXR，只有安卓 Chrome 能用。
Wi-Fi 信号定位网页读不到 Wi-Fi 信号强度。
GPS室内基本不可用。
天花板摄像头（预案一的做法）最准，参与者也不用拿手机，但要装设备，并且涉及拍摄。
